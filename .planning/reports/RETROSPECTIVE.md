# RETROSPECTIVE — AD SCRIPT STUDIO v1

> 작성일: 2026-08-01
> 대상: Milestone v1 (Phase 1~7) — 전략 제안서 생성기 + 영상 소스 생성기 + 벤치마킹 분석기
> 상태: v1 최종 완료 (프로덕션 배포 + E2E + PDF 한글 폰트 최적화 포함)

## 1. 잘된 것 (Keep)

1. **당위성 엔진을 프로젝트 핵심으로 격상한 리팩터링** — 초기 "대본 생성기" 정체성에서
   "전략 제안서 생성기"로 재정의. 이 결정이 v1의 가치를 결정함. 모든 후속 Phase가
   이 축을 중심으로 정렬됨.
2. **무료 우선 5단계 폴백 체인** — 자동 모드가 단일 API 모델에 의존하지 않도록
   폴백 체인을 구성해 가용성을 확보. 프로덕션 E2E에서 90초 지연에도 완료 보장.
3. **서버 강제 비용 상한** — 벤치마킹 분석기의 MAX_ANALYZE_REELS=5, maxTotalChargeUsd=1.
   외부 API 비용이 폭주하지 않도록 서버 상수로 강제. 유사 기능 추가 시 재사용 패턴.
4. **단계적 검증** — 로컬 검증 → 프로덕션 E2E → 육안 확인 순으로 검증 단계를
   밟은 것. 특히 PDF는 브라우저 검증만으로는 잡히지 않는 시각 문제가 있어
   최종 육안 확인이 결정적이었음.

## 2. 문제였던 것 / 실수 (Problem)

### 2-1. "구현 완료"와 "실증 검증 완료"를 혼동함
- Phase 6에서 "Milestone v1 완료"로 선언했으나, 프로덕션 배포 후 E2E를 돌려보니
  PDF 다운로드 5개 버그가 연쇄 발생 (commit c2c6294).
- **교훈: 검증 없이 완료 선언하지 말 것. "구현됨"은 "검증됨"이 아니다.**
  코드가 존재하는 것과 프로덕션에서 동작하는 것은 별개의 사실.

### 2-2. 서버리스 환경의 CDN/파일 접근 제약을 늦게 확인함
- 한글 폰트를 CDN(raw.githubusercontent.com)에서 fetch하도록 설계.
  CDN 의존 + 서버리스 환경 제약을 초기에 검증하지 않아, 타임아웃/실패 시
  한글 깨짐 이슈로 이어짐.
- **교훈: 서버리스 환경의 CDN/파일 접근 제약을 항상 먼저 확인할 것.**
  Vercel 정적 에셋 라우팅, 타임아웃 상한, 폰트 서브셋 크기를 설계 초기에 검증.

### 2-3. 다크 테마 텍스트 팔레트를 흰 배경에 적용함 (가독성)
- Proposal PDF에서 표지만 다크 배경으로 칠하고, 나머지 섹션은 배경 채우기를
  빠뜨린 채 다크 테마용 밝은 텍스트(224,224,224)를 흰 배경에 렌더링.
- PDF는 코드로 검증하지만 **시각적 가독성은 코드만으로 잡히지 않음**.
- **교훈: 색상 팔레트는 "배경 + 전경" 쌍으로 관리하고, 렌더링 후
  이미지 기반 검증(PyMuPDF 픽셀 검사)을 하거나 육안 확인을 필수로 할 것.**

### 2-4. PDF 검증 도구 미설치 상태로 검증 진행
- `pdftotext` 미설치 상태에서 텍스트 추출을 시도 → pypdf로 대체.
- **교훈: 검증 수단(도구)을 먼저 확보하고, 대체 도구(pypdf, PyMuPDF) 사용 시
  동일 결과를 교차 확인할 것.**

## 3. 유지할 프로세스 (Improve)

1. **Phase 완료 선언 전 실증 검증 게이트** — 로컬 → 배포 → E2E → 육안 확인
2. **외부 의존(CDN/API/폰트)은 배포 전에 접근성·크기·타임아웃을 검증**
3. **색상은 라이트/다크 테마를 명시적으로 하나로 통일** — 하이브리드는 금지
4. **비용이 발생하는 외부 API는 서버 강제 상한 적용**
5. **문서(SUMMARY/STATE)를 실제 검증 결과와 동기화** — "Planned"를 계속 붙여두지 않기
